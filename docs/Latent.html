BlueprintPseudocode guide

Latent and async nodes

Some nodes finish later than they are called: a Delay, an async node, a macro that waits. What runs when they finish is the => block under the call.

Latent nodes: => blocks

A node with the clock icon, such as Delay, runs what follows it later, when it finishes. The call ends in => and what runs later is indented under it. The lines under a => read values as they are when they run, not as they were at the call.

A loop runs all its passes in one frame, so a Delay in a loop body starts once, on the first pass, and the block under it runs once, after the loop. The line says so: // starts on the first pass only; runs after the loop. A Retriggerable Delay restarts instead: // restarts on every pass; runs once after the loop.

event OnDied()
    KismetSystemLibrary::Delay(2.0) =>
        Respawn()
In a loop
for (i = 0; i < Len(Enemies); i++)  // ForEachLoop
    KismetSystemLibrary::Delay(1.0) =>  // starts on the first pass only; runs after the loop
        Respawn()

Async nodes: Async Load Asset, Play Montage, AI Move To

An async node runs its plain output at once and its other outputs later. The plain output continues after the node, at its level. Each later output is a => block, written first, and the data the node delivers is the block's parameters. With one later output, => ends the call's line; with more, each wired output gets [Pin] =>.

Reading the node's data in the flow after the node, before the block has run, is marked as a read the flow did not set.

event OnInteract()
    AsyncLoadAsset(Icon) => (Object)
        ShowAsset(Object)

    UpdateHud()
Several later outputs
    PlayMontage(InSkeletalMeshComponent=Mesh, MontageToPlay=Reload, PlayRate=1.0, StartingPosition=0.0, StartingSection=FName("None"))
        [On Completed] => (NotifyName)
            FinishReload()
        [On Interrupted] => (NotifyName)
            CancelReload()

    UpdateAmmoText()

Macros and collapsed graphs that wait

A macro or collapsed graph is read through its own graph. An output it reaches only through a latent node inside it, a Delay for example, is a => block, like the Delay's own. One that some paths reach at once and others only after the wait says // may run now or later.

A macro with several outputs is a plain call over its blocks: [Pin] for an output that runs at once, [Pin] => for one that waits. An output fired from inside a loop in the macro runs on every pass, and its block says so: [Loop Body] // runs on every pass of a loop in LoopTwice.

for (i = 0; i < Len(Points); i++)  // ForEachLoop
    WaitThenSpawn(Points[i]) =>  // starts on the first pass only; runs after the loop
        ShowHint("spawned")
Several outputs
    FadeToBlack(1.0) =>  // may run now or later
        OpenMenu()

    PlayDeathAnimation(Death)
        [Anim Not Valid]
            EnableRagdoll()
        [Received Ragdoll Notify] =>
            FinishDeath()
