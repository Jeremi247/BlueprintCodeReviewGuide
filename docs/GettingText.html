BlueprintPseudocode guide

Getting the text

Three ways to get the text, from a quick review to a whole-folder sweep. All of them run on your machine.

Where the plugin is

The steps below name files in the plugin's folder, the one that holds BlueprintPseudocode.uplugin. In a project it is Plugins\BlueprintPseudocode\. Installed from Fab, it is a folder under the engine's Engine\Plugins\Marketplace\ with a generated name: look for the one that holds BlueprintPseudocode.uplugin.

Diff in P4V with Ctrl+D

One-time setup in P4V: Edit › Preferences › Diff, under "Specify diff application by extension" click Add, and set Extension to .uasset. The other two fields depend on whether the path of the plugin folder has a space in it.

No space in the plugin folder's path

  1. Application: the pythonw.exe that ships with your engine, e.g. C:\Program Files\Epic Games\UE_5.8\Engine\Binaries\ThirdParty\Python3\Win64\pythonw.exe (spaces are fine here)
  2. Arguments: <plugin folder>\Tools\BlueprintReader.py -Diff %1 %2, with no quotes

A space in the plugin folder's path - Workaround

A Fab install under C:\Program Files has one. P4V cannot pass such a path to Python, so a batch file you create does:

  1. Create a text file named BlueprintDiff.bat, e.g. in C:\Tools, holding this one line, with your engine's python.exe and your plugin folder in place of the two paths: 
    @"C:\Program Files\Epic Games\UE_5.8\Engine\Binaries\ThirdParty\Python3\Win64\python.exe" "<plugin folder>\Tools\BlueprintReader.py" -Diff %* || pause
  2. Application: C:\Tools\BlueprintDiff.bat
  3. Arguments: %1 %2

If a path in the batch file is wrong, its window stays open with the error.

Then Ctrl+D on a changed Blueprint opens both revisions in P4Merge as text. Unreal does not need to be running, but the engine must be installed. Assets that are not a Blueprint, string table or StateTree show a message instead.

The Python does not have to be the engine's. If you have your own, any 64-bit Python 3.7 or later works, e.g. one from python.org: put its pythonw.exe in Application, or its python.exe in the batch file. A 32-bit Python cannot load the plugin.

In the editor

Right-click one or more Blueprints, string tables or StateTrees › Pseudocode:

  1. Export to File: writes to Saved/BlueprintPseudocode and opens the file, or the folder for several
  2. Copy to Clipboard
  3. Diff Against Depot: one asset, your local version against the latest depot revision; needs source control connected

In Unreal's own Blueprint Diff window, or a StateTree's diff window in UE5 (for example from Source Control › History), click Pseudocode Diff next to Prev and Next to open the same two revisions as text in your diff tool.

All of these read the saved file. If a Blueprint has unsaved changes, you are asked once: Yes saves and converts, No converts the saved file and notes at the top that unsaved changes are not included, Cancel stops. A Blueprint that was never saved is skipped.

Command line

For whole folders, e.g. to grep across many Blueprints, without starting Unreal:

"C:\Program Files\Epic Games\UE_5.8\Engine\Binaries\ThirdParty\Python3\Win64\python.exe"
  "<plugin folder>\Tools\BlueprintReader.py"
  D:\MyProject\Content\Gameplay -OutDir=D:\BPText

Use the engine's python.exe, beside the pythonw.exe above, or any 64-bit Python 3.7 or later. It takes files and folders, searches folders recursively and skips what is not a Blueprint, string table or StateTree. Add -Engine= and -Project= when the engine and project are not found above the files.

The commandlet exports from the editor instead, as it loads each asset:

UnrealEditor-Cmd.exe MyProject.uproject
  -run=BlueprintPseudocode
  -Paths=/Game/Gameplay
  -Out=D:\BPText

Use -Assets=/Game/X/BP_A,/Game/Y/BP_B for single assets. On 4.27 the editor is UE4Editor-Cmd.exe. The loaded asset already has the engine's renames applied, so its text has no redirect lines.

Code reviews in web tools

P4 Code Review (Swarm) can show Blueprint pseudocode with a module the plugin ships: see Swarm setup. GitHub, GitLab and other web tools can't, since they cannot run the plugin on their server. For those, diff the Blueprints locally and comment in the review as usual:

  1. Open the review's changelist or shelf in P4V
  2. Press Ctrl+D on each Blueprint, or use Diff Against Depot in the editor
  3. Leave your comments in the review
